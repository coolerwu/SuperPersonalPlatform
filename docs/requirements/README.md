# 需求文档目录

本目录保存按需求编号落盘的需求文档，是需求口径的唯一来源。实现与验证都以这里
的文档为准，代码不能反过来定义需求。

## 命名与编号

- 文件名固定为 `F<n>-<名称>.md`，例如 `F3-群聊附件.md`。
- `<n>` 从 1 开始连续递增；新文档取本目录已有最大编号 +1，不复用已删除的编号。
- `<名称>` 用简短中文描述需求主题，不使用空格、斜杠或日期。

## 文档分档

大需求（新功能、跨模块改动，或涉及数据模型、接口、口径、迁移）必须包含：

- 文档头：状态、日期、范围、前置依赖。
- 背景与目标 / 用户故事 / 功能点清单 / 验收标准 / 约束边界 / 非目标 / 开放问题。

小需求（文案、单点微调、不改变口径的小修复）可以只写：

- 需求一句话 / 改动点 / 验收标准 / 边界不做的事 / 开放问题（可选）。

## 协作约定

- 需求文档由 `.codex/skills/omni-roles` 的〔req〕角色产出；〔req〕只负责意图、场景、
  边界和成功标准，不在文档里定技术路线或写实现代码。
- 没有需求文档覆盖的改动不进入实现，再小也一样。
- 需求确认后如发生口径变更，先回写对应 F 文档，再继续方案或实现。
- 该目录不替代 `docs/project-architecture.md`：F 文档描述"要做什么、做到什么算完成"，
  架构文档描述"系统实际怎么运行"。

## 与其他文档的关系

- `docs/project-architecture.md`：架构、运行约定与长期记忆索引。
- `docs/architecture-qa.md`：DeepAgent 重构的技术决策问答。
- `docs/release.md`：版本、发布与回滚流程。
