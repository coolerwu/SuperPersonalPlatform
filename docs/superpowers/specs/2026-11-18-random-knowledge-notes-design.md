# 随机笔记展示（知识库随机阅读）设计

- 日期：2026-11-18
- 状态：设计已确认，待实现
- 关联模块：`apps/api/app/services/knowledge_notes.py`（新增）、`apps/api/app/routers/knowledge.py`、`apps/api/app/config.py`、`apps/web/src/routes.ts`、`apps/web/src/components/Sidebar.tsx`、`apps/web/src/components/RandomNotesPage.tsx`（新增）、`apps/web/src/App.tsx`、`apps/web/src/api.ts`、`apps/web/src/types.ts`、`apps/web/src/styles.css`
- 关联需求：`docs/intent.md` F28 随机笔记展示（新增）、F9 知识库镜像

## 背景

- 知识库现状：F9 的 `KnowledgeSyncRuntime` 在 API 进程内把 WebDAV 目录双向镜像到 `knowledge/`，平台没有浏览页面，也不挂载给 Agent。
- 用户需求：做一个独立页面，**随机把知识库里的笔记原文展示出来**，随手翻看、回看巩固、偶遇旧笔记。注意：不是让 AI 把笔记加工成问答卡。
- 已确认的决定：
  - 随机展示**整篇笔记**，按 Markdown 渲染，长笔记在卡片内滚动；
  - **洗牌不重复**：本轮看过的先不再出现，全库看过一遍后自动重新洗牌，不记录学习状态（不做遗忘曲线、没有「会了/不会」）；
  - 不调用模型，不依赖 Provider，不新增数据表。

## 目标

1. 新页面 `/knowledge`：每次随机展示一篇 `knowledge/` 下的笔记原文，点「换一篇」抽下一篇。
2. 本轮内不重复；全库看完一轮后自动重新洗牌，并提示「本轮已看完，重新洗牌」。
3. 顶部显示本轮进度（已看 / 总数 / 剩余）。
4. 卡片上提供「追问」：切到聊天页并新建会话，输入框预置引用（笔记标题、路径、正文前 6000 字），用户在草稿后继续输入问题即可。

## 非目标

- 不做 AI 生成问答卡、遗忘曲线、间隔复习、会了/不会评分、收藏。
- 不做搜索、目录浏览、笔记编辑、按标签/目录筛选、原文跳转。
- 不把知识库挂载给 Agent，不改 F9 同步逻辑。
- 不新增 Python / npm 依赖，不新增环境变量，不新增数据表，不改部署架构。

## 现有约束

- 知识库目录 `settings.knowledge_dir`（`APP_KNOWLEDGE_DIR` 可覆盖，默认 `~/.super-personal-platform/knowledge`），只读使用。
- 运行时状态文件按 `knowledge_sync_state.json` 的惯例存 `data/` 下，原子写（临时文件 + fsync + `os.replace`）。
- 前端路由是自建 History API（`apps/web/src/routes.ts`）；非聊天页面用 `React.lazy` 分包；侧栏「Agent 能力」菜单当前含 技能 / 工具 / 插件 / 渠道 / 定时 / 记忆。
- 前端已有 Markdown 渲染组件 `Markdown.tsx`（聊天产物预览在用），直接复用。
- 前端没有单元测试运行器，验证以 vite 构建和浏览器实测为准。

## 设计

### 1. 扫描（`services/knowledge_notes.py`）

- 根目录：`settings.knowledge_dir`。
- 文件收集：
  - 只收 `.md` / `.txt`（扩展名不区分大小写）；
  - 跳过以 `.` 开头的文件和目录（`.obsidian`、`.git` 等）、符号链接、超过 2 MiB 的文件；
  - 读取失败的条目记 warning 并跳过。
- 标题：只读取文件前 8 KiB（`utf-8-sig` 解码），跳过 YAML frontmatter，取首个 `#` 级 Markdown 标题（忽略代码围栏内的标题，去掉尾部闭合 `#`）；没有则用文件名（去掉扩展名）。
- 索引：进程内缓存 `{相对路径: {title, size}}`，TTL 60 秒；根目录不存在或不可读时为空索引（不算错误）。相对路径用 POSIX 风格（如 `交易/缠论笔记/背驰判断.md`）。
- 正文在抽中时读取整文件（UTF-8，`errors="replace"`），不截断。

### 2. 洗牌状态 `data/knowledge_deck.json`

```json
{
  "cycle_started_at": "2026-11-18T09:00:00+00:00",
  "seen": ["交易/缠论笔记/背驰判断.md", "…"]
}
```

- 读取时：`seen ∩ 当前文件列表` 视为本轮已看，其余为未看；文件被删除/改名后其路径自然失效，新增文件立即进入未看池。
- 每次抽卡把抽中路径加入 `seen` 并原子写盘（单进程内用 `asyncio.Lock` 串行化读写）。
- 状态文件缺失、损坏或字段非法：视为新一轮（`seen` 为空），记 warning，不崩溃。
- 未看池为空即成轮结束：清空 `seen`、写入新的 `cycle_started_at`、`meta.notice` 返回「本轮已看完，重新洗牌」。

### 3. 抽卡规则

1. 扫描得到当前文件列表；计算未看池。
2. 未看池非空 → 从未看池随机取一篇；若请求带 `exclude` 且未看池多于一篇，先排除它。
3. 未看池为空（本轮看完）→ 重置本轮，从全部文件随机取一篇（同样尽量避开 `exclude`），带上面说的 `notice`。
4. 抽中后读取正文；读取失败则把该文件从本次候选中剔除重试，候选全部失败时返回 500「读取笔记失败」。
5. 知识库没有任何可用文件 → 404「知识库没有可用的笔记，先去配置页检查知识库同步」。

### 4. 接口

在 `routers/knowledge.py` 追加（沿用 `/api/knowledge` 前缀与 `require_auth`）：

- `GET /api/knowledge/notes/random?exclude=<相对路径>`：

```json
{
  "note": {
    "path": "交易/缠论笔记/背驰判断.md",
    "title": "MACD 与背驰",
    "content": "…原文 Markdown…",
    "size": 3263
  },
  "meta": {"seen": 12, "total": 57, "notice": ""}
}
```

- `meta.seen` 为加入本篇后的已看数；`meta.total` 为当前文件总数；`notice` 非空表示本轮刚重置。
- 错误：知识库为空 → 404；读取全部失败 → 500；未鉴权 → 401（沿用 `require_auth`）。
- `exclude` 参数可选，仅用于避免连续两篇相同。

### 5. 前端

- 路由：`routes.ts` 增加 `knowledge` → `/knowledge`；`App.tsx` 懒加载 `RandomNotesPage`。
- 侧栏：「Agent 能力」菜单里「记忆」之后新增「随机笔记」，进入时自动展开该菜单（沿用现有机制）。
- 页面结构：
  - 顶部进度行：「本轮已看 N / 共 M · 剩余 R」，本轮重置时在进度行旁显示临时提示「本轮已看完，重新洗牌」；
  - 中央一张玻璃卡片：头部为笔记标题、相对路径、文件大小；正文用 `Markdown.tsx` 渲染，卡片内滚动（限高约 60vh）；底部「换一篇」按钮；
  - 加载态：「正在抽下一篇…」骨架；错误态：错误文案 +「重试」；
  - 空库（404）：文案「知识库没有可用的笔记」+ 按钮跳转配置页知识库分区（复用侧栏分区直达机制）。
- 「换一篇」请求带当前笔记 `path` 作为 `exclude`，请求中禁用按钮；响应后用 `meta` 更新进度。
- 「追问」：
  - 点击后调用 App 现有的 `newSession()` 切到新会话，聊天页输入框预置引用草稿（复用现有 quote 机制，引用块以 `> ` 前缀拼进消息正文），用户在引用后继续写问题再发送；
  - 引用内容组成：首行「笔记：<相对路径>（完整原文：`~/.super-personal-platform/knowledge/<相对路径>`）」，随后是正文前 6000 字；正文超过 6000 字时追加一行「（已截断，完整内容见上方路径）」；
  - 路径让 full 权限 Agent 可自行读全文；workspace 权限 Agent 读知识库会被 hook 拒绝，但引用里的正文足以回答问题；
  - 纯前端实现，不新增后端接口。
- 不做前端持久化：刷新后从服务端状态继续（服务端记录本轮进度）。
- 样式沿用珍珠冷光 + 极光 + 玻璃风格；≤860px 时卡片占满宽度、正文限高按视口调整。

### 6. 边界与已知限制

- Markdown 中的相对图片/链接无法解析（知识库文件不通过附件接口提供），按现有 `Markdown.tsx` 行为渲染为文字/链接；本期不处理。
- 2 MiB 以上的文件不进池，避免一次渲染过大内容。
- 笔记内容变化但路径不变：本轮仍算已看（不会立刻重新出现），轮次重置后可再次抽到新内容。
- 同一笔记在文件系统里被移入隐藏目录或删除，会从池中消失。
- 追问引用截断到 6000 字；更长的笔记需要 Agent 自行读全文（仅 full 权限 Agent 可行）。

### 7. 测试

后端（pytest）：

- 扫描：扩展名过滤、隐藏目录/文件跳过、超大文件跳过、标题取首个 `#` 标题或缺省文件名、索引缓存 TTL 行为。
- 洗牌：本轮不重复、未看池耗尽自动重置并带 `notice`、`exclude` 生效、删除文件后从池中消失、新增文件进入未看池、状态文件损坏时按新一轮处理。
- 接口：mock 扫描结果与 tmp 目录；空库 404；正文读取成功/失败重试；`meta` 计数正确；响应只给相对路径与正文，不暴露服务器绝对路径。

前端：`npm run build`；手动验收（抽第一篇、换一篇不重复、看完整轮重置提示、空库态、追问跳转新会话并预填引用、移动端布局）。

## 风险与已知取舍

- 纯随机阅读没有「记住程度」概念，看过的笔记在本轮不会再出现，但也不会因重要而被加频——这正是「随手翻笔记」的取舍。
- 轮次状态只存服务端：多浏览器共用同一轮进度；重置轮次由「未看池耗尽」触发，不支持手动重置。
- 长笔记渲染依赖现有 Markdown 组件；2 MiB 上限兜底。
