# 前端性能与流畅度设计

- 日期：2026-11-12
- 状态：待评审
- 范围：`apps/web`（React + Vite），不改后端接口与视觉风格

## 背景

现有页面的实际体感问题：

1. 在聊天里发送消息后，视图不会自动跟随到新消息。
2. 打开或切换页面慢。
3. 滚动不流畅，输入和点击有延迟。
4. 聊天记录越长越卡，新建空会话明显更顺畅；桌面和手机都受影响。

用户明确要求保留珍珠冷光 + 极光 + 毛玻璃的视觉风格，优化只能从代码与渲染路径入手。

## 现状与诊断

以下都是当前代码里可核实的事实。

### 周期性全树重渲染

- `apps/web/src/App.tsx` 的 `SIDEBAR_POLL_MS = 5000`，每 5 秒拉一次会话列表。
- `applySessions` 无条件 `setSessions(list)`，即使内容完全相同也创建新数组，触发 App 全树重渲染。
- `ChatPanel` 是普通函数组件，没有 `React.memo`，因此每 5 秒都会把整条消息列表重新 map、重新协调 DOM，会话越长代价越大。

### 流式刷新重复计算历史消息

- `apps/web/src/useThrottledText.ts` 以 80ms 间隔刷新流式文本，`ChatPanel` 因此每 80ms 重渲染一次。
- 每次重渲染都会对全部历史消息调用 `processSteps`、`ArtifactStrip` 等派生逻辑，并重新创建整列 React 元素；`Markdown` 虽然有 memo，但父级 map 和协调成本仍随会话长度线性增长。
- 消息行没有独立 memo，任何一次父级重渲染都会重新计算所有行的执行步骤。

### DOM 随会话线性增长

- 消息列表没有虚拟化，长会话会积累成百上千个消息节点。
- 样式中有 19 处 `backdrop-filter`、持续运行的 `pearl-orb` 背景动画（16s 无限循环），滚动时合成与重绘成本高。
- 用户要求保留这些效果，因此优化重点是减少需要协调和绘制的 DOM 与提交次数，而不是关闭效果。

### 首屏与切页成本

- 构建产物：`index-*.js` 约 1.17 MB，`index-*.css` 约 138 KB，`dist` 合计约 2.4 MB（含全套 KaTeX 字体）。
- `App.tsx` 顶部同步 import 了全部 19 个页面组件（聊天、配置、记忆、技能、工具、插件、渠道、定时、回测、交易、配置、缠论等），首屏必须解析全部代码。
- 路由是自建的 History API 状态切换，没有按页面分包、没有预取，也没有页面数据缓存；每次切页都要重新发请求并挂载整页。

### 发送后不跟随

- `ChatPanel` 用 `stickRef` 记录"是否贴底"，`handleScroll` 根据当前位置是否接近底部来更新它。
- 长会话里图片、代码块、KaTeX 字体晚加载会改变内容高度，由此触发的 scroll 事件可能把 `stickRef` 误判为 false，之后新消息和流式增长都不再跟随。
- 发送时虽然会强制贴底一次，但后续布局变化仍可能把跟随状态关掉；移动端键盘收起导致视口尺寸变化时也没有重新贴底。
- 结论：跟随逻辑需要用"用户主动滚动意图"来判定，而不是只看当前滚动位置。需要在长会话里复现后修正式确认。

## 目标与非目标

### 目标

1. 发送消息、流式输出、排队追问、中断后继续的整个过程中，视图可靠跟随最新内容。
2. 聊天记录再长，输入、点击、滚动的体感保持稳定。
3. 首屏更快、已访问页面二次切换接近即时。
4. 视觉风格完全不变。
5. 每一步可独立交付、独立回退。

### 非目标

- 不关闭或削弱毛玻璃、极光动画、珍珠冷光风格。
- 不修改后端接口、SSE 协议和数据结构。
- 不引入状态管理库，不重写路由，不拆分 2095 行的 `App.tsx`。
- 不为前端新增测试框架（Vitest/Jest）；验证依赖构建、Profiler 和手工清单。
- 不做消息全文搜索、消息时间戳等新功能。

## 验收标准

在 300 条消息、含图片/代码块/公式/工具调用的会话里：

- 发送消息后 1 秒内视图贴底，新消息可见；流式期间持续跟随。
- 用户主动向上滚动后停止跟随；点"回到最新"恢复跟随。
- 输入框打字和按钮点击无可感知停顿：React Profiler 单次提交常规 < 16ms，长任务不连续出现；输入到字符上屏 < 100ms。
- 滚动时接近 60fps，Performance 面板无连续超过 50ms 的长任务。
- 已访问页面的二次切换 < 200ms；首次切换先显示骨架屏，不出现整页白屏。
- 首屏入口 JS 体积相对当前 1.17 MB 下降至少 30%。
- 毛玻璃、极光、珍珠冷光在桌面和手机上的观感与现在一致。

## 设计

按 P0 → P1 → P2 → P3 分阶段实现，每阶段单独提交。

### P0：修复发送后不跟随

新增 `useAutoFollow`（放在 `apps/web/src/`，由 `ChatPanel` 使用），把"是否跟随"从滚动位置判断改为用户意图判断。

- **用户意图来源**：滚动容器上的 `wheel`、`touchmove`、指针按下后的拖动（含滚动条拖动），以及获得焦点时的 `PageUp`/`PageDown`/`Home`/`ArrowUp` 等按键。只有这些输入造成的、且离开底部的滚动才把 `stick` 置为 false。
- **布局变化不关闭跟随**：`ResizeObserver` 或虚拟化测量触发行高变化后，在一个动画帧内忽略 scroll 事件对 `stick` 的影响，避免图片、代码块、字体晚加载被误判成用户上滚。
- **回到即恢复**：任何滚动只要落回底部附近，就把 `stick` 重新置为 true，覆盖滚动条拖动、键盘滚动等未被手势表捕获的路径。
- **程序性滚动不改变跟随状态**：调用 `scrollToBottom` 期间设置标记，期间触发的 scroll 事件只做校准，不关闭跟随。
- **强制贴底**：发送消息时立即置 `stick = true`，在下一帧和再下一帧各执行一次贴底，覆盖输入框收缩和列表插入造成的布局变化。
- **内容增长跟随**：保留 `ResizeObserver` 观察消息内容；`stick` 为真时在 `requestAnimationFrame` 里贴底。
- **移动端视口**：监听 `window.visualViewport` 的 `resize`，`stick` 为真时重新贴底，处理键盘收起后的视口恢复。
- **用户上滚暂停**：`stick` 为 false 时显示现有"回到最新"按钮；点击后置 true 并贴底。
- 保留现有"定位到某条消息"行为：显式定位时暂停跟随，定位完成后的用户滚动照常判定。

验收：在 300 条消息会话里复现原问题，修复后发送、流式、中断重试、排队追问四种路径都不再丢失跟随。

### P1：渲染隔离

**消息行独立并 memo**

- 把 `ChatPanel` 里的用户消息行、助手消息行、流式行抽成独立组件（例如 `MessageRow`、`StreamingRow`）。
- 行组件用 `React.memo` 包裹；`message` 对象保持引用稳定，`highlighted` 用布尔值传入，回调在 `ChatPanel` 里用 `useCallback` 固定。
- `processSteps`、产物列表、工具摘要等派生数据在行内 `useMemo`，只在 `message.blocks`/`message.content` 变化时重算。
- 流式刷新只改变流式行；历史行因 memo 直接跳过协调。

**面板 memo 与稳定 props**

- 把消息区域从 `ChatPanel` 中拆成 `MessageList`，让输入框草稿、附件上传进度、命令菜单这些只影响输入区的状态变化不再重渲染整条消息列表。
- `ChatPanel` 和 `MessageList` 都用 `React.memo` 包裹。
- 传入的数组和对象（`messages`、`activity`、`subagents`、`tasks` 等）已在 App 里按会话维护，保证未变化时引用不变；回调统一用 `useCallback`。

**轮询等值比较**

- 新增 `sessionSummariesEqual(a, b)`，逐字段比较 `id`、`title`、`busy`、`last_modified`、渠道字段等；相等时 `applySessions` 直接返回，不 `setState`。
- 页面不可见时跳过轮询 tick（保留 `visibilitychange` 立即刷新）。

**其他低成本修正**

- `MessageSkeleton`、错误横幅等只在对应状态出现，保持现状。
- 不在渲染函数里创建新对象作为 props；必要时用 `useMemo` 固定。

验收：300 条消息会话里，空闲时不再周期性提交整棵树；流式期间 Profiler 中历史行不重新渲染。

### P2：长会话虚拟化

引入 `@tanstack/react-virtual`（^3，约 10 KB）对消息列表做窗口化。

- **容器结构**：`.message-scroll` 仍是滚动容器；内部增加一个高度为总测量高度的占位层，可视行用 `translateY` 定位。错误横幅、骨架屏、空状态、流式行等保持非虚拟化或固定在末尾。
- **动态高度**：每个消息行挂 `measureElement`，图片、代码块、KaTeX 渲染完成后由库重新测量；图片的 `loading="lazy"` 改为可视区附近提前加载，避免滚动时突然撑高。
- **贴底**：消息数量增加或行高变化且 `stick` 为真时，用 `scrollToIndex(count - 1, { align: "end" })` 贴底；与 P0 的 `useAutoFollow` 共用判定。
- **定位消息**：`focusMessageId` 从 DOM 查找改为在消息数组里求索引并 `scrollToIndex`，定位后继续沿用现有的高亮闪烁。
- **会话切换**：历史加载完成后定位到末尾，不显示滚动中途的跳变。
- **窗口参数**：`overscan` 取 8 行左右，在 iPhone Safari 上以滚动无空白为标准微调。
- **已知取舍**：浏览器自带 Ctrl+F 只能找到已渲染的消息；页面不提供消息搜索，记录在设计文档中，不在本阶段新增搜索功能。

验收：1000 条消息的会话 DOM 消息行数量保持在一个固定窗口内；滚动无空白、无跳动；发送跟随、定位、复制、引用行为不变。

### P3：首屏与切页

**路由级代码分割**

- `apps/web/src/App.tsx` 保留聊天页和登录页的同步 import。
- 其余页面改为 `React.lazy(() => import(...))`，用 `Suspense` 包住页面区域，加载时显示与现有风格一致的骨架屏。
- 维护一个页面加载器表，供惰性加载和预取共用。

**空闲预取**

- 首屏稳定后（`requestIdleCallback`，降级为 2 秒定时）预取侧栏中最常用的页面 chunk（配置、定时、回测）。
- 侧栏项 hover/focus 时预取对应 chunk；已加载的 chunk 由浏览器缓存，不重复下载。

**vendor 拆分**

- 通过 Vite `build.rollupOptions.output.manualChunks` 拆出稳定的共享 chunk：React 运行时、Markdown 渲染链（`react-markdown`、`remark-*`、`rehype-*`、`katex`、`highlight.js`）、图表库（`lightweight-charts`）。
- 不改变任何运行时行为，只影响加载粒度与缓存命中。

**页面数据缓存**

- 新增模块级 `pageCache`（Map + 时间戳），为回测、交易、配置、缠论、资产配置、渠道、定时等列表接口提供 stale-while-revalidate：再次进入页面先用缓存渲染，同时在后台刷新，刷新成功替换。
- 缓存键包含 Agent 或查询参数；写操作成功后主动失效相关键，避免旧数据覆盖。
- 不改后端接口，不持久化到 localStorage。

验收：`vite build` 输出中入口 JS 相对当前下降至少 30%；已访问页面二次切换 < 200ms；首次切页显示骨架屏且无白屏；预取不阻塞首屏交互。

## 组件边界

| 单元 | 职责 | 依赖 |
| --- | --- | --- |
| `useAutoFollow` | 维护跟随状态、用户意图识别、贴底调度、视口变化处理 | 滚动容器 ref、内容 ref、当前消息数 |
| `MessageRow` / `StreamingRow` | 单条消息的渲染、派生数据 memo、复制/引用 | `message`、`agentId`、`highlighted`、回调 |
| `MessageList` | 虚拟化窗口、测量、定位、贴底协调 | 消息数组、`useAutoFollow`、virtualizer |
| `sessionSummariesEqual` | 判断轮询结果是否变化 | `SessionSummary[]` |
| `pageCache` | 页面级 stale-while-revalidate 缓存 | 接口函数、缓存键 |
| 页面 loader 表 | 路由懒加载与预取 | 各页面动态 import |

`App.tsx` 仍然负责全局状态与数据拉取；本设计不改变它的职责边界，只减少它触发的无效重渲染。

## 数据流

1. 发送消息：`ChatPanel.submit` → App 追加待确认用户消息 → `messages` 变化 → `stick` 已置真 → `MessageList` 贴底。
2. 流式输出：SSE 更新当前会话的 `streamText` → 80ms 节流 → `StreamingRow` 重渲染 → 历史行 memo 跳过 → 贴底调度执行。
3. 侧栏轮询：每 5 秒拉列表 → `sessionSummariesEqual` 比较 → 相等则丢弃，不触发重渲染。
4. 切页：路由变化 → 若 chunk 未加载则显示 Suspense 骨架 → 缓存命中先渲染旧数据 → 后台刷新。

## 错误处理与边界

- 虚拟化窗口与 `measureElement` 不修改消息数据，只影响渲染；测量失败时回退到估算高度，不阻塞滚动。
- 图片加载失败保留现有 alt 文本；不使用固定 `loading="lazy"` 导致窗口外图片永远不加载。
- 定位消息在虚拟化下索引越界时降级为贴底，不抛错。
- 页面 chunk 加载失败显示错误横幅和"重试"，与现有接口错误处理一致。
- `pageCache` 只缓存成功的响应；失败的请求不写缓存。
- 用户主动上滚后，流式内容继续在后台更新，视图停在原处；"回到最新"按钮逻辑不变。
- 中断、重试、排队追问、渠道消息、Slash 命令回复的现有行为全部保持。

## 新依赖

- `@tanstack/react-virtual` ^3：长会话窗口化。选择理由：动态行高测量成熟、体积小、维护活跃；自研需要处理图片/代码块高度变化等边界。已征得同意。
- 不引入其他运行时依赖，不新增测试框架。

## 风险与回退

- 虚拟化改变滚动结构，可能引入定位和贴底偏差；通过 P0/P1 先稳定跟随逻辑、P2 再动列表结构来隔离风险。
- `React.lazy` 可能让首次切页出现骨架屏；通过空闲预取和 hover 预取降低概率。
- `pageCache` 可能展示短暂旧数据；通过写操作主动失效和后台刷新收敛。
- 如果 P2 在 iPhone Safari 上无法达到无空白滚动，保留 P0+P1 交付，P2 回退后单独排查，不影响已解决的问题。
