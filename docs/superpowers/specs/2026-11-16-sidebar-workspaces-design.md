# 侧栏工作区重组（Agent / 管理）设计

- 日期：2026-11-16
- 状态：设计已确认，待实现计划
- 范围：侧栏信息架构与前端导航；不动路由路径、HTTP 接口与后端

## 1. 背景与目标

「Agent 能力」组（技能、工具、插件、渠道、定时、记忆）已从 Agent 工作区移入原「功能」工作区。迁移解决了 Agent 页签会话区被管理入口挤占的问题，但也带来两处语义问题：

1. 「功能」同时承载交易数据页和 Agent 能力配置，名字只表示「不是聊天」，无法说明这个页签的职责。
2. 配置页仍留在 Agent 页签，而「功能」页签里已经集中了其余非聊天页；管理入口被拆在两个页签。

目标：

- 给两个页签一个可长期沿用的语义：「Agent = 用，管理 = 管」。
- 让「管理」成为所有非聊天页的唯一入口，Agent 页签回到纯聊天职责。
- 保持 Agent 选择器在管理页可用（记忆、工具、渠道、定时都跟随当前 Agent）。

成功标准：

- 从任意页面都能一眼判断自己在哪个工作区，页签名与页面内容一致。
- 记忆、工具、渠道、定时、配置页不需要切回 Agent 页签就能切换 Agent。
- 页面深链接、刷新、浏览器前进后退行为不变。

## 2. 总体决策

| 决策 | 内容 | 理由 |
|---|---|---|
| 页签模型 | 保留两个页签 | 拆三个（Agent / 交易 / 能力）会让交易页独占一个页签；交易页与能力页同属「管理某样东西」 |
| 页签命名 | 「功能」改名为「管理」 | 页签多数内容是配置与管理入口，改名后与 Agent（聊天）形成「用 / 管」对照 |
| Agent 选择器 | 两个页签都常驻 | 记忆、工具、渠道、定时、配置都跟随当前 Agent；选择器是全站 per-agent 配置的唯一来源 |
| 配置页归属 | 移入「管理」的平台组 | 「管理」作为所有非聊天页的唯一入口；配置页本质是管理页 |
| 管理页落地 | 记住本次会话最后停留的管理页；初始值取当前路由（不在管理页时为回测） | 从聊天切到管理时通常想回上次位置，避免固定落到回测多一跳 |
| 页签点击 | 已在管理页时点击「管理」不跳转 | 页签表示工作区，重复点击不应改变位置 |
| 侧栏滚动 | 内容超出视口时整列纵向滚动 | 管理页签分组变多，矮窗口和手机抽屉不能截断入口 |

被否掉的方案：

- 三个页签：页签数量增加，交易页内容不足以支撑独立页签。
- 配置留在 Agent 页签：与「管理 = 所有非聊天页」的语义冲突，管理入口继续分裂。
- 管理页固定落地回测或记忆：实现简单，但每次切换都多一跳。

## 3. 侧栏结构

```
[Agent] [管理]                       ← 页签
Agent 选择器                          ← 两个页签共用
── Agent 页签（两个可折叠菜单）──
▾ Agent 工作台
  + 新对话
  会话列表
▾ Agent 能力
  技能 / 工具 / 插件 / 渠道 / 定时 / 记忆
── 管理页签（两个可折叠菜单）──
▾ 交易
  回测 / 交易记录 / 资产配置 / 缠论图
▸ 平台
```

- Agent 工作台、Agent 能力、交易与平台都是折叠菜单：默认全部展开，点击标题独立收起或展开。
- 进入某页时自动展开该页所在菜单（深链接、前进后退、页签落地）；展开状态只存在 React state，不持久化。
- 「Agent 能力」放在 Agent 页签，强调其中的记忆、工具等页面跟随当前 Agent。
- 「平台」菜单只在管理页签出现，含配置和退出登录。

## 4. 导航与状态

页面 → 页签映射（工作区判定）：

| 页签 | 页面 |
|---|---|
| Agent | `/chat`（含 `/chat/<session_id>`）、`/memory`、`/skills`、`/tools`、`/plugins`、`/channels`、`/cron` |
| 管理 | `/config`、`/backtest`、`/journal`、`/allocation`、`/chan` |

切换行为：

- 点 `Agent` → `openView("chat")`。
- 点 `管理` → 已处于管理页时不操作；否则打开 `lastFeaturesView`。
- `lastFeaturesView` 只存在 React state：初始值取首屏路由（当前是管理页则记为它，否则为 `/backtest`）；进入任一管理页时更新；不写 localStorage，刷新后按当前路由重新初始化。
- 路由路径不变，`/config` 仍为 `/config`；深链接、刷新、前进后退沿用现有 History API 逻辑。
- 切换 Agent 时（选择器）保持当前页面，只清空会话选择；管理页不跳转。
- 菜单跟随当前页自动展开对应组：能力页 → Agent 能力；交易页 → 交易；配置页 → 平台。

## 5. 边界情况

- 直接打开 `/memory` 等能力页：侧栏高亮「Agent」，Agent 选择器立即可用；点「管理」落到上次管理页。
- 刷新后从 Agent 切到管理：刷新时停在管理页则回到该页；刷新时在聊天页则落到回测。
- 窄屏（≤860px）抽屉：结构与桌面一致；侧栏 `overflow-y: auto` 让长分组可滚动。
- 退出登录只在管理页签的平台菜单里。

## 6. 验证

只改前端，后端无改动：

1. `cd apps/web && npm run build` 通过。
2. 手点验收：页签切换；从 `/memory` 点 Agent 再点能力菜单；从 `/backtest` 点 Agent 再点管理回回测；深链接直达四个交易页、配置页与六个能力页时高亮正确；刷新行为；窄屏抽屉滚动。
3. 无新增依赖、无接口与数据变化。
